# ECDICT

Free English to Chinese Dictionary Database.

## 簡介

這是一份英文->中文字典的雙解詞典數據庫，根據各類考試大綱和語料庫詞頻收錄數十萬條各類單詞的英文和中文釋義，並按照各類考試大綱和詞頻進行標註。

最初開發看書軟件時需要給軟件添加一個內嵌字典，在網上找到了一份別人提供的 EDictAZ.txt 的文本文件，裏面有差不多兩萬英文單詞的釋義，於是開始用這個文件來提供字典查詢，用着用着不夠用了，又找到一份四六級到 GRE 包含釋義的詞彙表，但是缺少音標，於是寫了個爬蟲從各種資料裏面把音標給爬下來，外加自己補充了一些組成了一份三萬基本詞彙的數據庫。

其後數年根據各種資料和網友貢獻詞庫增長到 10 萬左右，又找到 Linux 下面的 cdict-1.0-1.rpm 這個開源字典數據（mdict 的主詞庫也是根據 cdict 轉換得到），並按照英國國家語料庫的前 16 萬單詞進行校對，補全很多語料庫裏詞頻較高但是卻沒有收錄的詞條。

## 單詞標註

給數據庫中每個單詞標註：是否是各類考試大綱詞彙？以及他們在 BNC 和其他語料庫裏的詞頻順序。BNC 詞頻統計的是最近幾百年的歷史各類英文資料，而當代語料庫只統計了最近 20 年的，爲什麼兩者都要提供呢？

很簡單，quay（碼頭）這個詞在當代語料庫裏排到兩萬以外，你可能覺得是個沒必要掌握的生僻詞，而 BNC 裏面卻排在第 8906 名，基本算是一個高頻詞，爲啥呢？可以想象過去航海還是一個重要的交通工具，所以以往的各類文字資料對這個詞提的比較多，你要看懂 19 世紀即以前的各類名著，你會發現 BNC 的詞頻很管用。

而你要閱讀各類現代雜誌，當代語料庫的作用就體現出來了，比如 Taliban（塔利班），在 BNC 詞頻裏基本就沒收錄（沒進前 20 萬詞彙），而在當代語料庫裏，它已經冒到 6089 號了，高頻中的高頻。

BNC 較爲全面和傳統，針對性學習能幫助你閱讀各類國外帝王將相的文學名著，當代語料庫較爲現代和實時，以和科技緊密相關。所以兩者搭配，幹活不累。

經過標註後，你查任何一個單詞，都會告訴你這個詞彙是不是四六級詞彙？雅思詞彙？柯林斯星級是多少？是否是牛津 3000 核心詞彙？傳統詞頻和現代詞頻各是多少？這樣單詞的重要程度你就能瞭解個大概了。

其次是標註動詞的各個時態，每個動詞有現在分詞，過去式，過去分詞，第三人稱現在時等四種時態，用 NodeBox 和 WordNet 工具包可以方便的查詢每個動詞的變化形式，如此你查單詞時能夠給你顯示出來各種變體，同時將這些變體作爲新的生詞再次加入到字典中，大部分字典都沒法查詢動詞的各種時態，ECDICT 可以讓你方便的查詢一萬多個動詞（幾乎所有動詞）的所有派生詞。

## 數據格式

採用 CSV 文件存儲所有詞條數據，用 UTF-8 進行編碼，用 Excel 的話，別直接打開，否則編碼是錯的。在 Excel 裏選擇數據，來自文本，然後設定逗號分割，UTF-8 編碼即可。

| 字段        | 解釋                                                       |
| ----------- | ---------------------------------------------------------- |
| word        | 單詞名稱                                                   |
| phonetic    | 音標，以英語英標爲主                                       |
| definition  | 單詞釋義（英文），每行一個釋義                             |
| translation | 單詞釋義（中文），每行一個釋義                             |
| pos         | 詞語位置，用 "/" 分割不同位置                              |
| collins     | 柯林斯星級                                                 |
| oxford      | 是否是牛津三千核心詞彙                                     |
| tag         | 字符串標籤：zk/中考，gk/高考，cet4/四級 等等標籤，空格分割 |
| bnc         | 英國國家語料庫詞頻順序                                     |
| frq         | 當代語料庫詞頻順序                                         |
| exchange    | 時態複數等變換，使用 "/" 分割不同項目，見後面表格          |
| detail      | json 擴展信息，字典形式保存例句（待添加）                  |
| audio       | 讀音音頻 url （待添加）                                    |

提供一段 Python 程序來讀取這些數據，可以用它轉換到 SQLite 和 MySQL 的數據庫裏，方便你用更高級的方法篩選查詢。詞條數據大小寫不敏感，不論從查詢還是排序，還是編程接口。

## 詞形變化

某個動詞的各種時態是什麼？某個形容詞的比較級和最高級又是什麼？某個名詞的複數呢？這個單詞是由哪個單詞怎麼演變而來的？它的原型單詞（Lemma）是什麼？

可能大家注意到上表有一個 `Exchange` 字段，它就是來做這個事情的，這是本詞典一大特色之一，格式如下：

```text
類型1:變換單詞1/類型2:變換單詞2
```

比如 perceive 這個單詞的 exchange 爲：

```text
d:perceived/p:perceived/3:perceives/i:perceiving
```

意思是 perceive 的過去式（`p`） 爲 perceived，過去分詞（`d`）爲 perceived, 現在分詞（'i'）是 perceiving，第三人稱單數（`3`）爲 perceives。冒號前面具體項目爲：

| 類型 | 說明                                                       |
| ---- | ---------------------------------------------------------- |
| p    | 過去式（did）                                              |
| d    | 過去分詞（done）                                           |
| i    | 現在分詞（doing）                                          |
| 3    | 第三人稱單數（does）                                       |
| r    | 形容詞比較級（-er）                                        |
| t    | 形容詞最高級（-est）                                       |
| s    | 名詞複數形式                                               |
| 0    | Lemma，如 perceived 的 Lemma 是 perceive                   |
| 1    | Lemma 的變換形式，比如 s 代表 apples 是其 lemma 的複數形式 |

這個是根據 BNC 語料庫和 NodeBox / WordNet 的語言處理工具生成的，有了這個 Exchange ，你的 App 能爲用戶提供更多信息。

## 編程接口

代碼 stardict.py 用於操作該數據（兼容 Python 2/3），同時實現三個類：

| 類名      | 說明                                                                    |
| --------- | ----------------------------------------------------------------------- |
| DictCsv   | 用於讀寫 ecdict.csv 數據格式文件                                        |
| StarDict  | 用來讀寫 SQLite 詞典數據文件，數據字段和上面相同，接口也和 CSV 版本相同 |
| DictMySQL | MySQL 版本的數據文件讀寫，同樣字段和接口和上面兩者相同                  |

以上三個類都統一提供如下接口：

| 接口        | 說明                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------- |
| query       | 查詢單詞，可以查整數 id（CSV 裏 id 爲行號，其他兩者是自增量）或單詞字符串，返回 Python 字典 |
| match       | 單詞匹配，匹配最相似的前 N 個單詞                                                           |
| query_batch | 批量查詢                                                                                    |
| count       | 返回數據庫詞條總數                                                                          |
| register    | 註冊新單詞                                                                                  |
| update      | 更新單詞數據，除了 id, word 兩個字段外其他都可以更新                                        |
| remove      | 刪除單詞                                                                                    |
| commit      | 提交更改                                                                                    |

在 stardict.tools 下面還有很多幫助類的接口，便於你維護詞典數據：

1. 導出兩個字典數據的差異
2. 導入差異數據到一個字典
3. 導出成 StarDict（星際譯王）的原格式（用於 DictEditor 生成字典）
4. 導出成 mdict 的 .mdx 的源文件（用於 MdxBuilder 生成 mdx 字典）
5. 詞典格式 .csv, .db (Sqlite), mysql 之間數據互轉。

## 詞幹查詢

這個詞幹不是背單詞時候的詞根，而是 lemma。每個單詞有很多變體，你編寫一個抓詞軟件抓到一個過去式的動詞 gave，如果字典裏面沒有的話，就需要詞幹數據庫來查詢，把 gave 轉變爲 give，再查詞典數據庫。

我掃描了 BNC 語料庫全部 1 億個詞條語料生成的 lemma.en.txt 就是用來做這個事情，stardict.py 中 LemmaDB 這個類就是用來加載該數據並進行分析的。

你或許希望統計某些文檔的詞頻，然後針對性的學習，那麼你需要先將文章中出現的詞先轉換成該詞的原型（lemma），網上有很多算法做這個事情，但是都不靠譜，最靠譜的方式就是數據庫直接查詢，著名的拼寫檢查庫 hunspell 庫就是這麼幹的。

用 LemmaDB 類可以方便的查詢 ['gave', 'taken', 'looked', 'teeth'] 的 lemma 是 ['give', 'take', 'look', 'tooth']，也可以查找 'take' 這個詞的若干種變體。

這個 lemma.en.txt 涵蓋了 BNC 所有語料的各種詞彙變形，95%的情況下你可以查到你想要的，這個作爲首選方法，查不到再去依靠各種算法（判斷詞尾 -ed，-ing 等），最可靠的是數據庫，算法次之。

## 單詞詞性

數據庫中有一個字段 pos，就是中文裏面的詞性，動詞還是名詞，英文叫做 [pos](https://www.nltk.org/book/ch05.html) ，句子中的位置。同樣是掃描語料庫生成的，比如：

fuse：pos = `n:46/v:54`

代表 fuse 這個詞有兩個位置（詞性），n（名詞）佔比 46%，v（動詞）佔比 54%，根據後面的比例，你可以知道該詞語在語料庫裏各個 pos 所出現的頻率。關於 pos 裏各個字母的含義還可以看 [這裏](http://www.natcorp.ox.ac.uk/tools/xaira_search.xml?ID=POS) 和 [這裏](http://www.natcorp.ox.ac.uk/docs/c5spec.html)。

## 詞典使用

同時支持 CSV, SQLite, MySQL 三種格式，github 上放的字典數據是 .csv，因爲基於文本，便於 PR 和更改看 differ，但是本地使用 csv 很痛苦，文件大了打開速度很慢。所以自己使用時，一般都是轉換成本地的 SQLite 數據庫，這樣快速很多，基本沒有等待，查單詞也很迅速。

日常使用，比如整理自己的卡片，生成 anki 數據等，SQLite 是首選，stardict.py 中提供完整的 SQLite 字典接口。如果自己要修訂，建議先新生成一個比較小的 .csv，配合本地的大的 SQLite .db 數據庫一起用，查一個單詞時先查小的 .csv 裏面有沒有，沒有的話再去查 SQLite 的庫去，這樣現在 .csv 裏面把修訂的工作幹了，自己用一段時間沒大問題，數據比較穩定的時候，一次性從 .csv 中合併到大的 SQLite 數據庫中。
不合並也行，同時使用兩個庫。

如果你要提交 PR，可以把你的整個 SQLite 數據庫導回 .csv 格式，然後在網上提交 differ 或者 patch。本地可能有多個 SQLite 數據庫，一個就是這個 ECDICT 的數據，一些可能是你從其他什麼某些資料裏面導出來的比較好的釋義例句等，就是你日積月累整理收集的各種材料。

生成 Anki 卡片的時候，你可以優先使用你自己的庫的信息，你自己的庫裏沒有了，再找 ECDICT。而 ECDICT 裏面的各種詞頻標註，考試大綱標註，也可以給你提供不同層次的參考。比如你想把託福裏面去除六級的詞彙篩選出來（很多重合），這時 EDICT 本身的標註信息就能讓你方便的完成這個工作了，你也可以把詞頻三萬以下的單詞導出來成爲 Excel，進行更多處理。

**最新版數據太大，我已經把數據庫壓縮成 stardict.7z 了，外面默認的 ecdict.csv 算是一個基礎版本（76 萬詞條）。**

## 模糊匹配

數據庫中有一個隱藏字段，叫做 `sw`，這是 strip-word 的縮寫，意思是單詞字符串經過 strip 以後的結果。這裏的 strip 不是 python string.strip 那樣簡單的把頭部尾部的空格去除，而是去除整個字符串中非字母和數字的部分，並將字母轉爲小寫，對應代碼爲：

```python
def stripword(word):
    return (''.join([ n for n in word if n.isalnum() ])).lower()
```

CSV 數據庫雖然沒有記錄該字段，但每次加載到內存以後會自動爲每個單詞生成該字段，而 SQLite/MySQL 數據庫則是建表的時候就包含該字段，插入單詞時爲該單詞自動計算後插入，以後不再改變。

這是參考 Mdx 詞典格式引入的模糊匹配鍵值，當你使用 stardict.py 中的 match 方法時，如果第三個參數爲 True，將會使用 `sw` 字段進行匹配。默認 False 使用 `word` 字段匹配時，是嚴格匹配字符串，那麼你搜索 "long-time" 這個單詞，只能匹配到 "long-time" 開頭的所有單詞，比如：

    long-time, long-time base, long-time period, long-time cycle, ...

但是如果進行模糊匹配，按照 `sw` 字段匹配 "long-time" 這個單詞，將會搜索出所有 `sw` 以 "longtime" 開頭的單詞，比如：

    long-time, longtime, long time, long-time base, longtime base, ...

單詞隨着時間的推移，最開始是一個詞組，然後變爲一個減號鏈接的組合詞，最後用的多了，減號也省了。很多詞典裏不一定能完全包括 long-time/long time/longtime 這類詞的所有形態，但首次查詢搜索失敗時，可以 match 一下相同 sw 的單詞，然後能夠定位到該單詞的其他形態。

很多詞典，如星際譯王都不包含 strip 字段，因此常常詞典中有該單詞，但是由於你輸入了錯誤的形態，導致你查不出來，而 ECDICT 作爲一個負責任的詞典數據庫，能夠讓你通過 `sw` 這個字段任意查詢單詞的各種形態。
